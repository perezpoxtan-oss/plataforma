# Auditoría de seguridad 2026-10-06 — Infraestructura, despliegue y exposición de archivos

Rama: `feature/seg-infraestructura` · Alcance: carpeta pública y `.htaccess`, `despliegue/desplegar.sh` y la estructura que deja en Neubox, flujos de GitHub Actions, configuración de Laravel (`.env`, sesión, dominio), comandos de consola peligrosos, respaldos de la base y dependencias.

## Resumen para el dueño (sin tecnicismos)

Intentamos "romper" la forma en que la plataforma se instala y se publica en el servidor. **No encontramos una puerta abierta para que alguien de fuera entre o se lleve la base de datos**: el código y la configuración viven fuera de la carpeta pública, los respaldos solo los descarga el Super Administrador y cada descarga queda registrada.

Sí encontramos varios puntos donde un error humano o una cuenta comprometida podía hacer daño, y ya quedaron cerrados:

1. **Producción podía instalar un paquete cambiado a escondidas.** Si alguien con acceso a GitHub reemplazaba el paquete de una versión ya autorizada (por ejemplo `v1.0.0`), el servidor lo instalaba solo. Ahora cada versión de Producción queda "sellada" con su huella digital: si cambia, no se instala. También se puede escribir la huella autorizada en `desplegar_version.txt`.
2. **Correos con enlaces a sitios falsos.** Un usuario con sesión podía hacer que los avisos por correo (por ejemplo, el de "alta provisional" que llega a Recursos Humanos) llevaran un enlace a otro sitio, útil para robar contraseñas. Ahora la plataforma solo responde a su propio dominio.
3. **Producción con modo de depuración.** Nada impedía subir la configuración de Producción con `APP_DEBUG=true` (los errores mostrarían detalles internos) o con un nombre de ambiente mal escrito (que apaga los candados de Producción). Ahora el instalador se niega y hay una plantilla `despliegue/env_prod.txt` lista.
4. **Otros refuerzos:** el token de GitHub ya no se ve en la lista de procesos del servidor, los respaldos ya no incluyen sesiones abiertas, el navegador recibe instrucciones de seguridad (no incrustar la plataforma en otros sitios, usar siempre HTTPS), el `.htaccess` niega archivos sensibles aunque alguien los copie por error a la carpeta pública, y los flujos de GitHub quedaron con permisos mínimos.

Lo único que **requiere que usted haga algo** está al final, en "Pasos en cPanel y GitHub".

## Pasos en cPanel y GitHub (requieren al dueño)

1. **Comprobar el `.htaccess` en QA** (después de que se instale esta versión). Desde cualquier terminal o https://reqbin.com:
   - `curl -I https://qa.vdcp.com.mx/.htaccess` → debe ser **403**.
   - `curl -I https://qa.vdcp.com.mx/storage/` → **403** o **404** (nunca un listado).
   - `curl -I http://qa.vdcp.com.mx/login` → **301** hacia `https://`.
   - `curl -I https://qa.vdcp.com.mx/login` → debe traer `X-Frame-Options` y `Strict-Transport-Security`.
   - `curl -I -H 'Host: otro.example' https://qa.vdcp.com.mx/login` → **400** (o la página por defecto de Neubox).
   Si el sitio diera error 500 o un ciclo de redirecciones, el despliegue regresa solo a la versión anterior; avísenos.
2. **Producción:** crear `env_prod.txt` a partir de `despliegue/env_prod.txt` (contraseña real de la base) y subirlo a `/home/vdcpcomm` con el Administrador de archivos. Si ya existe Producción, su `.env` debe decir `APP_ENV=production` y `APP_DEBUG=false` o el instalador se detendrá avisando en `despliegue_prod_estado.txt`.
3. **GitHub → Settings → General → Releases → "Enable release immutability"** (versiones inmutables): GitHub impedirá cambiar el paquete de una versión publicada.
4. **GitHub → Settings → Rules → Rulesets → New tag ruleset**: objetivo `v*`, restringir creación, actualización y borrado a los administradores. Así solo usted autoriza versiones de Producción.
5. **Token de GitHub del servidor:** debe ser *fine-grained*, solo el repositorio `plataforma`, permiso *Contents: Read-only*, con fecha de vencimiento. Anotar la fecha para renovarlo.
6. **Respaldos descargados:** guardarlos cifrados (por ejemplo 7-Zip con contraseña AES-256) y fuera de la carpeta Descargas; contienen las contraseñas cifradas (hash) de todos los usuarios.
7. **cPanel → Administrador de archivos → `public_html`:** buscar y borrar respaldos viejos de SEGCAT (`*.sql`, `*.sql.gz`, `*.zip`, `*.bak`) que hayan quedado en carpetas públicas del sistema anterior.
8. **cPanel → MultiPHP INI Editor** (para los subdominios `qa` y `app`): `display_errors = Off`, `expose_php = Off`.
9. **Permisos de la carpeta principal:** en el Administrador de archivos, `/home/vdcpcomm` debe ser `711` y `~/apps/plataforma-*` `750` (el script ya lo ajusta).
